# B1 实验评估（四模型 × 10 runs）

评估日期：2026-07-13。范围仅包含 B1（naive prompt），不包含 B2/B3。四个模型分别汇总，不跨模型计算稳定性。

## 结论先行

- **GPT-5.5 的跨 K 主质量指标和暂定技能语义稳定度最好**：TSQE cell agreement 为 `0.741 ± 0.022`，技能集合 Jaccard 为 `0.941`；但 TSQE 领先 Claude (`0.729 ± 0.038`) 的幅度不大，10 次重复尚不足以把这解释为稳健的模型优胜。
- **Gemini 3.5 Flash 的矩阵与诊断重复稳定性显著最高**：暂定技能集合 Jaccard `0.929`、modal-K 比例 `0.80`、对齐 Fleiss κ `0.945`、分类 ARI `0.913`。8 个 K=5 runs 中只有 2 种对齐后的 Q 矩阵，其中同一个矩阵出现 7 次。代价是它的 TSQE 均值最低 (`0.708`)：这是“稳定，但不一定最接近数据参照”的典型例子。
- **Claude Sonnet 5 的综合质量较均衡**：TSQE 第二 (`0.729`)，专家 Q 匹配最高 (`0.923`)，K=5 条件下 SRMSR 最低 (`0.073`)；但 K 稳定性只有 `0.70`，矩阵/诊断稳定性也明显弱于 Gemini。
- **DeepSeek V4 Flash 当前风险最大**：modal-K 比例最低 (`0.60`)、分类 ARI 最低 (`0.715`)，并且 2/10 runs 有结构错误（某个技能只被 1 道题测量）。
- **没有单一“总冠军”**：GPT 偏质量，Gemini 偏稳定性与 token 效率，Claude 较均衡，DeepSeek 暂不建议作为 B1 首选。

## 技能语义稳定性（暂定标注，待人工确认）

每个 codebook 技能先根据名称和定义映射到规范技能类别，再把每次 run 表示为一个规范技能集合。任意两个 runs 的技能稳定度定义为 Jaccard：

`共同技能数 / 两次 run 合计出现的不同技能数`

例如，run A 为 `{同分母减法, 通分, 借位}`，run B 为 `{同分母减法, 通分, 约分}`，共同技能有 2 个，合计不同技能有 4 个，所以 Jaccard 为 `2/4 = 0.5`。每个模型有 10 runs，因此共有 `10×9/2 = 45` 对，表中报告 45 对的均值和标准差。

| 模型 | 平均 pairwise Jaccard ↑ | 最低值 | 不同规范技能集合数 ↓ | 最常见集合出现次数 ↑ |
|---|---:|---:|---:|---:|
| GPT-5.5 | **0.941 ± 0.081** | **0.833** | **2** | **8/10** |
| Gemini 3.5 Flash | 0.929 ± 0.097 | 0.800 | **2** | **8/10** |
| DeepSeek V4 Flash | 0.864 ± 0.121 | 0.667 | 3 | 6/10 |
| Claude Sonnet 5 | 0.855 ± 0.160 | 0.571 | 4 | 7/10 |

暂定 taxonomy 包括：同分母减法、异分母通分与减法、整数被减数/操作数处理、无需借位的带分数减法、借位/重组、不正规带分数规范化、带分数与假分数转换、分数约分、一般分数减法。

对 DeepSeek 逐 run 复核后可以看到，它的技能体系其实相当一致：6 个 K=4 runs 都以“混合数/假分数转换、通分、同分母减法、约分”为核心；3 个 K=5 runs 在此基础上加入“借位/重组”；唯一 K=6 run 再加入“整数部分相减”。因此差异主要来自 K 所代表的粒度，而不是名称随机漂移。初版规则曾把 `Subtract Fractions` 和 `Subtract like denominators` 错误拆成两个类别，导致 DeepSeek 被低估为 `0.685`；修正同义映射后为 `0.864`。

Claude 的 10 个 runs 也稳定保留“同分母减法、异分母通分、借位/重组、假分数部分规范化”四个核心技能。常见 K=5 ontology 在此基础上加入“整数/纯整数操作数处理”；K=4 只保留核心四项；两个 K=6 runs 分别增加“无借位带分数减法+约分”和“带分数操作+整数—分数交互”。初版规则把 run8 的 `Whole-to-Mixed Conversion` 误归为一般的“带分数↔假分数转换”，但其定义实际是为了处理整数减分数，应该归入整数操作数处理；修正后 Claude 从 `0.805` 上升到 `0.855`。

Gemini 的 8 个 K=5 runs 使用同一套五技能；两个 K=4 runs 使用同一套四技能，把“不正规分数处理”并入了借位/重组而没有单列。K=5 之间和 K=4 之间的 Jaccard 都是 `1.0`，跨 K 为 `4/5=0.8`，45 对平均得到 `0.929`。原始文本也高度重复：7 份 K=5 codebook 逐字相同，2 份 K=4 codebook 逐字相同，只有 run7 是同义改写，因此 Gemini 同时具有很高的词面和语义稳定性。

GPT 的 8 个 K=5 runs 都稳定保留“同分母减法、异分母通分、无借位带分数减法、借位/重组、假分数部分规范化”五技能；两个 K=6 runs 只额外加入“纯整数被减数分解”。K=5/K=6 内部 Jaccard 都为 `1.0`，跨 K 为 `5/6=0.833`，平均得到 `0.941`。初版规则把 run5 的 `Subtract mixed and whole numbers` 因包含 `whole numbers` 误归为纯整数被减数处理，但其定义实际是无借位带分数减法；修正后 GPT 从 `0.889` 上升到 `0.941`。值得注意的是，GPT 的10份原始 codebook 文本都不完全相同，说明它是“词面多样、语义稳定”，与 Gemini 的模板式重复不同。

当前暂定结果是 GPT 的技能语义集合最稳定，Gemini 紧随其后，DeepSeek (`0.864`) 与 Claude (`0.855`) 接近且都较高。但这**目前不能作为最终人工主结果**：196 个技能实例的 `review_status` 都还是 `draft_ai`。`codebook_annotations_draft.csv` 保存了原始名称、定义、规范类别和审核状态，人工可逐行修订并把状态改为 `human_confirmed`；之后重跑汇总即可得到最终结果。embedding 没有参与当前分数，未来只作为敏感性检查。

## 结构问题

DeepSeek run3 的 S05、run5 的 S04 都只被 1 道题测量，违反最少 2 道题覆盖的结构规则。其余 38 runs 没有结构错误。所有模型仍有不同程度的“某技能缺少单属性题”警告；GPT 平均最少（1.6/run），Claude 最多（3.4/run）。

## 验证结论

**Share with caveats。** 逐 run 指标、结构检查、modal-K 矩阵稳定性和分类 ARI 已完整计算；40/40 runs 可追溯。技能语义稳定性已有可审计的暂定分数，但人工确认尚未完成。对外使用时还必须披露：专家 Q 指标不惩罚未匹配技能、跨模型 token 不等价、GPT 有遗留失败标记，以及每个模型只有 10 次重复。
