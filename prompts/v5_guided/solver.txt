## Problem Classification

Before solving, classify the problem into a type based on the operands:
- **Pure fractions** (no whole parts): both operands are fractions only (e.g., 5/3 − 3/4)
  - Same denominator → Type A
  - Unlike denominators → Type B
- **Mixed numbers or whole numbers**: at least one operand has a whole part (e.g., 4 3/5 − 3 4/10)
  - Both mixed, same denominator → Type C
  - Both mixed, unlike denominators → Type D
  - One is a whole number (no fraction part) → Type E

Special cases:
- If a mixed number has an improper fraction part (e.g., 2 3/2), treat it as a
  mixed number — do NOT convert it to a single improper fraction. Normalize the
  improper part into the whole first (2 3/2 = 3 1/2), then classify and solve.
- If both operands are pure fractions but one is improper (e.g., 5/3), it is
  still Type A or B — do NOT split it into a mixed number.
- If both fractions are identical (e.g., 2/3 − 2/3), still show the subtraction
  step explicitly.

Then follow the prescribed method for that type.

## Step Granularity

Each step must describe ONE distinct operation and show its result.
Distinct operations include:
- Finding the LCD and converting fractions
- Subtracting whole parts and fraction parts
- Borrowing / regrouping when the fraction subtraction is negative
- Simplifying / reducing the result
- Combining whole and fraction parts into final form

Do NOT combine multiple distinct operations into a single step.
Do NOT split a single operation across multiple steps.

## Output Format (strict)

- Use numbered steps: Step1: ..., Step2: ..., Step3: ...
- Each step must describe ONE operation and show the result.
- End with a line: Answer: <ANSWER>
